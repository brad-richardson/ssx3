# 120 fps plan of record — September 17, 2026 (evening)

Owner: the Claude session that wrote this. It holds the plan, the gates, every
verdict read, and `docs/numbers-ledger.md`. Muse sessions execute the briefs
below and hand back receipts. Two spikes are reserved for reasoning-class
agents and are gated on wave-1 results. Nothing in a brief authorizes a
conclusion; the owner reads the receipts and writes the verdict.

Definition used throughout: **avg 120 fps** = 120 distinct presented frames per
second, counted at display present time, averaged over a full stock race on the
Odin 3's 122 Hz panel, with the game speed at 1.00 and the sim at 60 Hz or
120 Hz. Duplicates and swaps that land inside one refresh do not count.

## Why the plan looks like this

Measured on the Odin 3 (Snapdragon 8 Elite, 2 prime cores at 4.32 GHz, 6 at
3.53 GHz, Adreno 830, 122 Hz panel), stock Snow Jam via `m3-menu.dtm`:

| Fact | Value | Source |
| --- | --- | --- |
| Update callback CPU, median | 3.3 ms | t7smooth probe |
| Render callback CPU, median | 10.1 ms (includes interpolation upload) | t7smooth probe |
| Other emulation-thread work per tick | ~3 ms (inferred) | M7: thread ~98% busy at 60 Hz |
| Video thread busy | 0.19–0.38 core | M7; affinity race window |
| Race pace, pinned, uncapped | 1.00–1.07× (±20% bracketing) | affinity-summary.json |
| Pause-tail pace, pinned, uncapped | 1.97× | same (this is NOT race pace) |
| Prime-core clock under saturated load | 3.07 of 4.32 GHz, thermal status 0 | M4 notes (unmeasured since) |

The emulation thread is saturated at 60 Hz. A 120 route that re-enters the
guest renderer needs ~1.6× (60 Hz sim + extra guest render) or ~1.8× (120 Hz
sim). A route that produces the second frame off the emulation thread (host
FIFO replay with interpolated matrices, or GPU reprojection) needs no
emulation-thread headroom and lands on the two resources with slack. So:

1. Wave 1 measures the three unmeasured multipliers on the emulation thread
   (prime-core clock policy, deterministic-GPU harness tax, FP-fault storm) and
   the video-thread capacity for replay.
2. Wave 0 runs in parallel on the desktop: cheap runtime fixes with A/B
   receipts, the stock-track corpus, and phase 1 of the upstream LLVM backend.
3. Wave 2 branches on wave-1 numbers: replay context spike if capacity passes;
   LLVM phase 2 if phase 1 boots; clock policy if the sampler shows 3.07 GHz.

Upstream DolRecomp (post-Aug-10 pin) already ships register allocation across
instructions (native ABI), direct guest-to-guest calls, leader-only entries,
proven-pointer memory access, cold FP fixups, IR-instrumentation PGO, and
`--targets aarch64`. Upstream ModernGekko defaults new ports to it. The
one-chunk C-emitter pruning spike (agent 43) is INCONCLUSIVE and stays parked;
its staged patch is on the SSD under `android-spike/codegen/`.

## Rules every brief follows

- **One device agent at a time.** Before any Odin run: `adb -s <odin-serial> shell
  ps -A | grep moderngekko` must be empty, and `/data/local/tmp/mg/LEASE` must be
  absent or contain your brief id. Create it with your brief id at start,
  remove it at the end. A foreign lease means stop and report.
- **One emulator run on the Mac at a time.** Before any desktop emulator run:
  `pgrep -f moderngekko` must be empty and `/tmp/ssx3-host-lease` must be
  absent or yours. Same create/remove rule. Builds are allowed alongside a
  foreign lease only if the brief says so; verdict-grade A/Bs are never run
  while a build is running.
- **Receipts, not prose.** Every run keeps: run.json (or the desktop receipt),
  stderr/stdout, post-run Dolphin.ini and GFX.ini, screenshots, module sha,
  runner sha, movie sha, and any sampler log. Acceptance is computed by a
  script that prints a table. Write `REPORT.md` with the table, the exact
  commands, the file list, and a "what I could not do" section. Do not write a
  verdict; the owner does.
- **Vehicle discipline.** Every race number is screenshot-verified as racing
  (HUD timer visible). Menu pace is never reported as race pace. Uncapped
  means `EmulationSpeed = 0.0`, never 10. Report host CPU-ms per guest frame
  per thread as the primary number; speed is pass/fail.
- **Movie validity.** A movie is valid for a build only if a control run of it
  reaches the race and the strict dispatch compare matches a prior control. A
  stalled or diverged movie is reported, not measured.
- **Tree hygiene.** Touch only the files the brief lists. Commit only those
  files, one commit, `git add <path>` per file, message prefixed `[<brief id>]`.
  Never `git add -A`, never amend, never edit `docs/todo.md`,
  `docs/numbers-ledger.md`, or this file. Evidence goes to the SSD
  (`/Volumes/Extreme SSD/android-spike/<brief id>/`) for device work and to
  `local/research/<brief id>/` for desktop work. Never write into
  `third_party/` or `local/` build trees owned by another brief.
- **Headless etiquette.** There is no human in the loop. If a step needs a
  decision the brief does not cover, take the conservative option, record it
  in REPORT.md, continue. If blocked, write REPORT.md and stop. Stop at the
  first crash, hash mismatch, or foreign process, and report it.
- **Disk.** The Mac's root volume has under 2 GB free. Build and clone on
  `/Volumes/Extreme SSD/`. Never `brew install` anything.

## D1 — Odin measurement matrix (device)

**Question.** How much emulation-thread throughput is hidden behind three

**Non-goals.** No verdicts. No runtime code changes. No trial kinds. No

**May touch.** `tools/android_trial.py` (new flags only), `tools/odin_sampler.sh`

`/Volumes/Extreme SSD/android-spike/D1/`.

**Setup facts.** Device serial `<odin-serial>`, files under `/data/local/tmp/mg/`.
Templates: `user-m6h` (capped, the trial template) and `user-aff-tpl`
(`EmulationSpeed = 0.0`, uncapped). Binaries on device: `moderngekko-run-pace-egl`
(FIFO fix + throttle fix, sha `84de2c22…`), `moderngekko-run-trial` (trial TU,

**Step 0: sampler.** Copy `aff-sampler.sh` to `tools/odin_sampler.sh` and add,

`/sys/class/kgsl/kgsl-3d0/gpuclk`. Keep the existing per-thread CPU and PSR
columns. Add `--sampler` to `android_trial.py run` that pushes the script,
starts it at launch against the real PID with a 1 s interval, and pulls its

**Step 1: arms.** All arms: `m3-menu.dtm`, EGL, idle on, screenshots every
2 s (needed to verify racing), `--sampler`, `--affinity emu=80,video=40` unless
stated, template `aff-tpl` (uncapped) unless stated. Run each arm twice,
interleaved A B A B, never back to back same arm. Wait until every `cpu-*`

**Step 2: FP-fault rate.** Every run's stderr carries the shutdown counters

## M2 — Runtime micro-fixes with movie A/B receipts (desktop)

**Question.** Three small costs the M7 profile names and no review lists.
Each is landed only with an A/B receipt.

**May touch.** `native/patches/recompcore-platform.patch` (new hunks),
the live vendor tree under `third_party/ModernGekko/vendor/dolphin` for those
hunks only, one record test per fix under `tests/`. Evidence to
`local/research/M2/`.

**A/B instrument.** `tools/gamecube_movie_ab.py` (read its docstring). Capped
1.0, single core, quiet host, cool Air (wait until the fanless Air has idled
10 minutes between legs and record the leg order A B B A). Vehicle: a movie
that verifiably races on the current build; `local/research/perf-batch2/det-record-1.dtm`
and the F-spike `det-base-run.dtm` are candidates; the DSS2/EBC3 family
stalls at the briefing and is banned. Verify the vehicle with a control leg
and screenshots before the first A/B. Primary number: CPU-ms per riding
callback over the matched prefix; report the pair noise from a base-vs-base
pair first.

**Fix A: rounding-mode sync.** `StaticRecompCore_Sync.cpp::SyncOut` calls
`PowerPC::RoundingModeUpdated(ppc)` unconditionally at every burst boundary;
M7 shows it plus `SetSIMDMode` at 0.51% of cycles. Call it only when the
FPSCR RN or NI bits changed since the last SyncOut. Record test: the guard
is present. A/B receipt.

**Fix B: FP-unavailable vector.** The codegen spike counted 41,022
FP-unavailable faults in 25 s on the desktop (`android-spike/codegen/RESULTS.md`).
Each fault leaves native code, syncs, runs the `0x800` vector interpreted, and
syncs back. `native/research.md` describes how the syscall vector at `0xC00`
was moved into the core (`emulate_syscall_vector`); do the same for the
FP-unavailable vector: verify the seven-or-so words at `0x80000800` match the
SDK's `__OSFPUnavailable` prologue, and perform the vector body natively
(the SDK handler that follows is already native code). First measure: count
faults per second and attribute the two faulting ops the spike mentions
(guest PCs from the dispatch samples). Then implement, then A/B. If the
vector body does more than the syscall vector did (it loads the current
context and branches), stop after the measurement and report the disassembly.

**Fix C: fallback-JIT code-space poisoning.** M7 shows
`ARM64CodeBlock::PoisonMemory` at 0.32% on the emulation thread during play.
Find what calls `ClearCache`/`ClearCodeSpace` during a race:
`StaticRecompCore_Run.cpp` line ~192 forces `InvalidateICache(lr, 4, true)` on
the fallback yield path. Count the calls per second on the desktop with a
temporary counter (not committed). Report the caller and the rate; propose,
do not implement, unless it is a one-line guard with an obvious A/B.

**Deliver.** `local/research/M2/REPORT.md` with three A/B tables, the movie
sha, leg order, host temperature notes, and the patch hunks committed only
where the A/B is clean.
