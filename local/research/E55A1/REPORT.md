## Narrow fixed-clock recommendation and tests

Use `PS2X_DETERMINISTIC=1` with the existing exact-`"1"` environment pattern (`ps2xRuntime/src/lib/Kernel/Stubs/MPEG.cpp:729-743`). A narrow branch in `sceCdReadClock` can fill the same eight bytes from a fixed **UTC calendar value** while the unset/default branch retains its current `std::time` plus localtime path. Recommended value: **2004-07-16 12:34:56 UTC**. This is a calendar constant, so no host `TZ`, `mktime`, or `localtime` conversion is needed in deterministic mode. Expected reply: `00 56 34 12 00 16 07 04`. Byte-by-byte BCD and the derived little-endian input words appear in `~/dev/ssx3-work/E55A1/clock-table.txt`: `w0=0x12345600`, `w1=0x04071600`, `w0 ^ (w1<<3)=0x320ce600`. The table also computes the six destination words for this static path. All eight guest input bytes should match across boots independent of host date/timezone; this does not establish full-frame determinism.

Suggested tests (not run under this audit): with valid guest RAM/stack pointer, deterministic calls should return 1 and reproduce all eight bytes on repeated calls, including after changing host `TZ`; invalid guest pointer should return 0 without a write. With the flag unset, bracket the call with host time reads, convert the bracketing instants by the host's local timezone, and accept the corresponding BCD reply (or retry if a second boundary is crossed); this checks passthrough without encoding today's date. Check both `"0"` and unset follow that default branch. Existing environment-test save/restore practice is at `ps2xTest/src/ps2_runtime_kernel_tests.cpp:790-820`. Other E55 sources—idle event ordering, pad state, memory-card state—remain separate (`docs/research/review-2026-09-23-frontier-2.md:165-190`).
