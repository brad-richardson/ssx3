## Correct-behavior mapping: one 512×224 field

For a selected non-promoted circuit1 input with `SUPER_SAMPLES=1`, output `(x,y)`, `0<=x<512`, `0<=y<224`, reads `X=DBX+x`, `Y=DBY+phase_offset+y*phase_stride` (`gs/shaders/sample_circuit.frag:98-115`). The renderer passes raw `DISPFB1.{FBP,FBW,DBX,DBY}`, `rect.{phase_offset,phase_stride}`, PSM, VRAM size mask, and sample count (`gs/gs_renderer.cpp:4292-4313`). `compute_circuit_rect` sets `phase_stride=2` only for alternative interlace sampling and computes valid half-height there (`gs/gs_renderer.cpp:4327-4376`). Require `rect.valid_extent=512×224`; ignore cleared padding in `rect.image_extent` (`gs/gs_renderer.cpp:4273-4289`).

The shader calls `swizzle_PS2(X,Y,FBP*32,FBW,PSM,vram_size-1)`; `32` is `PGS_BLOCKS_PER_PAGE`, and FBW is a page stride, not a pixel stride (`gs/shaders/sample_circuit.frag:115`; `gs/shaders/data_structures.h:116-126`; `gs/shaders/swizzle_utils.h:329-342`). Its address is a 32-bit word index for PSMCT32 or a 16-bit element index for PSMCT16/S and PSMZ16/S, after byte-mask wrap (`gs/shaders/swizzle_utils.h:376-379`, `:418-420`, `:457-459`, `:477-479`). For PSMCT32, interpret the fetched word as little-endian RGBA bytes. For 16-bit, the shader expands each five-bit RGB component by `<<3` and maps alpha bit to 0/255 (`gs/shaders/sample_circuit.frag:56-70`; `gs/shaders/utils.h:61-86`). For other non-16 PSMs, the shader loads a word and forces alpha `0x80` unless PSMCT32 (`gs/shaders/sample_circuit.frag:60-70`); do not substitute FIFO's three-byte PSMCT24 output (`gs/gs_util.hpp:76-85`).

The actual source is chosen after the renderer rejects promoted images with too few layers (`gs/gs_renderer.cpp:4451-4458`); `sample_quad[promoted ? 1 : 0]` binds either promoted texture or `buffers.gpu` (`gs/gs_renderer.cpp:4278-4282`). `GSInterface` looks up promotion by FBP and passes candidates (`gs/gs_interface.cpp:5540-5552`, `:5576-5578`). The helper's FIFO caller maps host VRAM for transfer readbacks (`gs/gs_interface.cpp:4126-4147`), while GPU and CPU buffers alias only on the UMA path (`gs/gs_renderer.cpp:360-396`). Thus a census requires an ordered copy of the **selected** GPU source; the G40 staging mechanism shows a GPU-to-host B-page copy (`gs/gs_renderer.cpp:1614-1634`), but it is not an N8D6C input receipt.

## Bounded CPU adapter

For non-promoted, count-1 sampling, reuse `vram_readback<PSM>` on a contiguous complete VRAM slice from the GPU buffer. It calls `swizzle_PS2` in host C++ and emits tightly packed raw 32-/16-bit pixels (`gs/gs_util.hpp:49-93`; `gs/shaders/swizzle_utils.h:11-16`, `:329-342`). Dispatch PSMCT32 and PSMCT16/S explicitly, with other shader-supported PSMs only after matching load/alpha behavior. Pass `FBP*32`, raw FBW, `DBX`, and shader `vram_size-1`. For stride 1, one width-512/height-224 call uses `src_y=DBY+phase_offset`. For stride 2, call the helper 224 times with `height=1`, output offset `y*512*bytes_per_pixel`, and `src_y=DBY+phase_offset+2*y`. That one-row adapter is the smallest missing coordinate loop: helper `effective_y=(y+src_y)&2047` cannot express a two-line step in one call (`gs/gs_util.hpp:57-66`). Guard any X/Y reaching 2048: shader coordinates are passed unmasked to swizzle while helper masks them to 11 bits (`gs/shaders/sample_circuit.frag:108-115`; `gs/gs_util.hpp:59-66`). A later per-pixel loop could remove that guard.

Expand raw output into RGBA according to the shader, then count host pixels per 16×16 tile: occupied pixel when `max(R,G,B)>=32`, active tile when occupied pixels `>=32`, totaling 32×14=448 counts for this field (`ps2xRuntime/src/lib/gs/ps2_gs_parallel_backend.cpp:465-483`). Record raw slice and decoded-field hashes, geometry, controls, full tile counts, and copy/map errors. A complete 4 MiB base VRAM slice plus 458,752-byte RGBA field and bounded metadata is below 4.75 MiB; stage circuit image adds 458,752 bytes, so cap combined captures below 5.25 MiB. These are proposed limits, not measured allocations. An independent host readback of circuit1 is still needed to separate S from T; the existing stage tile compute is not that census (`gs/gs_renderer.cpp:4773-4786`; `ps2xRuntime/src/lib/gs/ps2_gs_parallel_backend.cpp:341-430`).

The helper and shader independently **execute** on CPU and GPU, but both call the same `swizzle_PS2` address algorithm (`gs/gs_util.hpp:66`; `gs/shaders/sample_circuit.frag:115`). Their agreement tests integration, coordinates, payload, and source capture; it does not independently validate the swizzle algorithm. Synthetic golden offsets or an external reference are required for that claim.

## Script-checkable synthetic fixture for the next brief

Design only; no fixture generator or test was run. A script should allocate zeroed 4 MiB raw VRAM, fill selected addresses with nonuniform known payloads, run the candidate adapter, and compare **all 512×224 RGBA pixels** plus hashes and 448 tile counts to a separately generated expected array. Use literal expected coordinates `X=DBX+x`, `Y=DBY+phase+stride*y` and a separate golden-address table for boundary pixels; never create expected output by calling `vram_readback` or the same swizzle function. For 32-bit vary payload by x, y, and case, e.g. `(R,G,B,A)=((17x+3y+11)&255,(5x+13y+29)&255,(7x+19y+47)&255,(x+23y+61)&255)`; for 16-bit independently choose 5-bit RGB and alpha bit, then expect shader expansion `<<3` and 0/255. Initialize unused locations to a sentinel; assert changing each parameter alters at least one expected pixel.
