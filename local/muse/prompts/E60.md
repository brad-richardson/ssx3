## Facts (E59)

- The sky, sun and flare return **only** when *all* of E53's VU0 group
  (a) is reverted (VSQI/VLQI/VCALLMSR/CMSAR1 back to the old wrong
  behaviour). The new behaviour matches PCSX2 for each op. **So E53
  exposed a second bug.**
- Reverting only VCALLMSR, only VSQI, or both doesn't bring it back. What
  remains is **VLQI at `0x3feb8c`** in `sceVu0MemReadQ` (it now reads VU0
  data at `vi1*16`; it used to read EE RAM) and CTC2 CMSAR1 at `0x3fed54`
  (never executed).
- The sky-like packet (PSMT8 256², TBP0 11017, from programs
  0x22c8/0x2270) is drawn in both runtimes, but with different state:
  - ours: `ALPHA=0x1`, CBP 10756;
  - PCSX2: `ALPHA=0x2a`, CBP 14473, and different MIPTBP1.

  So the draw state around the sky differs, not the geometry.
- Hypothesis: VU0 data memory doesn't hold what it does on the PS2. VIF0
  UNPACK/MPG transfers to VU0 are missing or wrong, or VU0 microprograms
  write the wrong results. Guest code reads that memory through
  `sceVu0MemReadQ`, and the value feeds the sky's render state (blend,
  palette) or a visibility/fade decision. The old EE-RAM read happened to
  return something that looked right.
