## Facts (orchestrator, 09-23)

- The game's VU1 microcode library is one image in the ELF data. Our `MPG
  addr=0` uploads are sourced at EE `0x435bf8` (ELF file offset `0x336bf8`;
  head `8000033c 100002ff 800c68f0 000002ff 81d26b7c …`). The code PCSX2 runs
  at VU1 slots 0/2/8 (`40000072`, `40000048`, `400000f2`) sits at EE
  `0x4349b8`, **0x1240 bytes (584 instructions) earlier in the same image**.
- So the game computes a different source offset for the same upload. Either
  game state differs (a different microcode set chosen) or a recompiled EE
  instruction computes the offset wrong.

## Change (default off, unit-tested, one commit)

`PS2X_MPG_SRC_TRACE=<file>` (+`_FROM`/`_TO` vsync, cap 2000 lines):
1. In the DMA chain walker, for every VIF1 REF/REFS/REFE tag whose payload
   carries an MPG (or whose `addr` falls in `0x430000–0x440000`): `mpgsrc
   vsync=<n> tag_at=0x<EE addr of the tag> id=<0/3/4> qwc=<n> addr=0x<ref
   addr> tte_vif=<8 hex bytes>`.
2. A guest write watch on the tag's `addr` word: the first time a new
   `tag_at` is seen, arm a watch on `tag_at+4` for the next run of the chain
   builder (or log writes for the rest of the window): `tagwrite vsync=<n>
   addr=0x<tag_at+4> value=0x<> pc=0x<guest pc> ra=0x<> fn=sub_<>` plus the
   GPRs used to compute the value (`$a0–$a3,$v0,$v1,$t0–$t9` at the store).
   Reuse existing watch mechanisms if the runtime has them (cite).
