## Scope: one batch, "R5900/VU0 semantics batch 1", driven by your failing tests

1. **Structural COP2:**
   - VSQI/VLQI (and VSQD/VILWR/VISWR if the code path is shared): use the
     correct fields, and target **VU0 data memory** (4 KiB wrap), not EE
     memory;
   - VCALLMSR reads CMSAR0 (`vu0_cmsar0`);
   - CTC2 CMSAR1 starts VU1 like PCSX2 (`vu1ExecMicro`);
   - VRINIT/VRNEXT/CTC2 R/CFC2 R use PCSX2's R register format and LFSR,
     and VRNEXT writes ft.
2. **Special values:**
   - DIV.S: a zero or denormal divisor gives ±FMAX with sign fs⊕ft;
   - VDIV/VSQRT/VRSQRT use PCSX2's rules (sqrt|x|, ±FMAX, and VRSQRT
     uses fs);
   - VFTOI0 positive overflow gives 0x7FFFFFFF;
   - FPU MAX.S/MIN.S use the sign-magnitude integer compare;
   - C.EQ/LT/LE operands: denormal → 0, Inf/NaN → ±FMAX, as `fpuDouble`
     does.
3. **FP mode:**
   - Compile the runtime and the generated code with
     `-ffp-contract=off`, so FPU MADD isn't fused. Show that the E50
     runner's `fmadd` count drops to the VU-intended sites, or to zero.
   - On the **EE game thread only**, set AArch64 FPCR round-toward-zero
     plus FZ (x86: MXCSR RTZ + FTZ/DAZ) at thread start. Make it
     env-switchable (`PS2X_EE_FPMODE=ieee|ps2`, default `ps2`) so we can
     A/B it. Verify the VU1 core's own scoped rounding still works, and
     that the host GS/present threads are unaffected.
4. **Not in this batch:** per-op Inf/NaN operand clamping (G2) and result
   clamping (G3). Report the performance cost estimate only.
