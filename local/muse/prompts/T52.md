## Why

At Select Character PCSX2's render chains contain four extra uploader
CALLs (sub-chains for 3D objects) that the recomp's chains lack, and the
chain arenas sit at different heap addresses: the recomp's scene builds
fewer objects. A likely cause is asset data that never loads. The recomp's
Snow Jam load also stops reading the CD at 99%. We need PCSX2's healthy list
of CD reads to diff against the recomp's.

## Mission

1. A **fresh boot** (not a statefile) through T47's route to Select
   Character settled, with a bounded log of every CD read the IOP performs:
   `cdread seq=<n> vsync=<ee vsync> lbn=<> sectors=<> mode=<> dest=<IOP
   addr or ->` (PCSX2's CDVD read path; its built-in CDVD trace or a
   log-only hook), plus, if cheap, `cdsearch name=<> lbn=<> size=<>` for
   `sceCdSearchFile`-style lookups and any ioman `open` name.
2. Mark screen transitions with vsync anchors (title, main menu, character
   select entry, SC settled) from the pad script times / F8 shots.
3. Table: reads per phase (count, total sectors), the distinct LBN ranges
   read during the **main menu → Select Character** transition and while
   SC is on screen, and any file names.
