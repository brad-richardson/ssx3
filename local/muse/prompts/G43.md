## Why

G42's Turnip leg stopped at `HAL has no GetInstanceProcAddr`. The
orchestrator traced that to **our hunk, not the driver**: `G42HalDevice`
leaves out `hw_device_t`'s `reserved` block. AOSP
`hardware/libhardware/include/hardware/hardware.h` (LP64):
`uint32_t tag; uint32_t version; struct hw_module_t *module; uint64_t
reserved[12]; int (*close)(struct hw_device_t *);` and
`hwvulkan.h`: `hwvulkan_device_t { hw_device_t common;
EnumerateInstanceExtensionProperties; CreateInstance; GetInstanceProcAddr; }`.
So `GetInstanceProcAddr` is at byte **136**; G42 read offset 40, a reserved
slot (always 0). The Turnip question (does B land under Turnip?) is still open.

Model of correct behavior: with the fixed layout, `close`@112,
`EnumerateInstanceExtensionProperties`@120, `CreateInstance`@128,
`GetInstanceProcAddr`@136 are all non-null code pointers inside the Turnip
`.so`'s mapped text range. Alternative: they're null or outside the `.so`
(then the HAL path really is unusable from a shell binary; stop, table it).
