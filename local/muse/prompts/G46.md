## Method: the discriminator

For 3 frames (Select Mode, Select Peak, and a loading or menu frame with
snowflakes), on the current Mac build:

1. Capture the recomp's GS input for that frame: the GIF packets plus
   priv regs plus any image uploads. Use GB2's capture tap
   (`gb2-gs-queue` `c937929`; cherry-pick onto a worktree off `ssx3` if
   needed), or E7/E4 if they're sufficient. Also capture our CPU backend's
   output frame.
2. Replay the same stream through **paraLLEl-GS** (the ps2xGS harness / the
   G44 shadow) and, if a converter to PCSX2's `.gs` dump format is
   feasible in ≤2 h, through **PCSX2's gsrunner** on bytesize.
3. PCSX2 reference screenshots of the same screens from its own run (T48
   route to Select Peak/Mode; the statefiles on bytesize are fine).

Per artifact, classify it:
- **(a) CPU-backend bug:** paraLLEl or PCSX2 render our stream cleanly.
- **(b) the game's draws are wrong:** every renderer shows it on our
  stream, and PCSX2's own run doesn't. That points upstream, at EE/VU
  or data.
- **(c) authentic:** PCSX2's own run shows it too.

For (a), find the mechanism in `gs_cpu_backend.cpp`: sprite XY/UV
fixed-point and texel centres, REGION_CLAMP/REPEAT, CLUT CSA/CLD
loading, TEX0/TEX1 LOD/MMIN/MMAG, alpha test, and the texture page
cache. Take the font spacing and the snowflake squares first.
