## Why

The milestone needs working input on the Odin. Today only the scripted pad
exists (`PS2X_PAD_SCRIPT`, vsync clock from E33). The runtime already reads
raylib gamepad 0: `ps2xRuntime/src/lib/ps2_pad.cpp:41-90` has buttons,
triggers and both sticks. Whether raylib's Android backend sees the Odin's
built-in controller, and with the right mapping, is untested.

## Steps

1. **Test what exists** (no code change, current N4 APK): launch to the
   title with no pad script, then inject gamepad keys:
   `adb shell input keyevent KEYCODE_BUTTON_START`, `KEYCODE_BUTTON_A`,
   `KEYCODE_DPAD_DOWN`, … Screencap before and after each key.
   Also run `adb shell getevent -lp` to record the controller's device name,
   keycodes and axis ranges.
   Table: key → PS2 bit expected → menu reaction yes/no.
   Note: injected keyevents may come from a virtual keyboard, not the
   gamepad. If so, say so, and also map `KEYCODE_BUTTON_*`/DPAD as keys.
2. **Fix what's missing** (one change set, on `n2-android`, Android-only
   `#if` blocks where needed):
   - the gamepad/keycode → PS2 button mapping (including Odin face-button
     positions: A = cross, B = circle);
   - analog sticks into the pad's analog bytes, if the pad handler reports
     DualShock mode;
   - the manifest items still open in `docs/todo.md` (N lane) if missing.
   Keep `PS2X_PAD_SCRIPT` working, since it takes precedence when set.
3. **Validate:**
   - One build.
   - A launch where injected keys drive title → main menu → Select
     Character. That's the same route as N4 launch 2, but with no script.
   - A 60 s idle check that no phantom input occurs.
   - Ask the orchestrator to have Brad press a few physical buttons: this
     is a hands-on check, so report it as a blocker with the exact 30 s
     test and don't wait on it.
