## Why (orchestrator read)

N4 found Select Character on the Odin VU1-bound at ~0.2 guest vsyncs/s.
The time goes to `__addtf3`/`__extendsftf2`, which are TFmode quad
soft-float. The VU1 core computes exact FMAC results in `long double`
(`ps2xRuntime/src/lib/vu/ps2_vu1_core.cpp:210-252, 407-412, 485`;
`include/runtime/ps2_vu1.h:300-301`):
- on **macOS arm64**, `long double` is the 64-bit `double`;
- on **Android/Linux arm64**, it's 128-bit IEEE quad, done in software.

So the Mac, our reference that matched PCSX2, already computes in
`double`. Using `double` everywhere makes the Odin compute exactly what the
Mac does. That's the hypothesis to test, with two alternatives:
- (a) Odin quad and double already give bit-identical results, so the only
  change is speed;
- (b) they differ on some inputs, and the Mac-equal one (double) is the one
  we want.

The observable that tells these apart is a result hash per variant.
