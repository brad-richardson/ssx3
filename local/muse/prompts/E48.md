## Facts (E46 Part 2)

- `0x3b1140` isn't in the canonical function table, so every boot skips it
  silently (×3, first at tick ~246, from `0x3b0698`, a vtable call at
  `obj+52`).
- It's a refcount release: `v0 = [a1+16] - 1`, store, return if > 0, else
  unlink the node. All three calls pass `a1 = 0x548840`: 3→2→1→0, then an
  unlink.
- Enabling it (codegen `~/dev/ssx3-work/codegen-ssx3-e463b1140`, which is
  `0x396b40` + `0x3b1140`) turns the screen black from tick 246 on. The
  resume-entry mechanism was verified correct.

**Orchestrator hypothesis to test:** node `0x548840` is a UI element.
Because the release is skipped, it's never unlinked and stays drawn. That
would explain the stray controller/button glyphs over Select Character
(G44: they're in the game's draw stream). With the release enabled, the
unlink corrupts or ends something that our runtime built differently
earlier.
