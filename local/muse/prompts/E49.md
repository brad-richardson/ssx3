## The mechanism (E48, orchestrator-accepted)

- The guest ends a movie when its end check `0x402b38` reads a nonzero
  word at `[[mpeg+0x40]+0]`. The runtime's MPEG HLE only ever writes 0
  there (`MPEG.cpp:2939`), and `0x402b38` isn't bound to an HLE.
- Today each bypassed movie ends only because the skipped release
  `0x3b1140` leaks the codec's single pool node: the 2nd alloc returns 0.
- Enabling `0x3b1140` makes the pool refill, so movie 1 plays blank
  frames forever and the screen goes black.

## Change (one mechanism)

1. In the MPEG HLE, once playback has ended, write 1 to the end word that
   `0x402b38` reads:
   - on the bypass path when `streamEnded` is set;
   - on the faithful path at producer EOF with the frame queue empty.

   Resolve the exact address the way the guest does: `[mpeg+0x40]`, where
   mpeg is the handle the HLE already receives. First read `0x402b38`
   with `ee-at` and cite it. Don't bind an HLE at `0x402b38` unless the
   write isn't possible. If you have to bind one, justify it.
2. Add `"0x003B1140"` to `extra_function_starts` in `games/ssx3/ssx3.toml`.
   Regenerate into `~/dev/ssx3-work/codegen-ssx3-e49`; don't touch
