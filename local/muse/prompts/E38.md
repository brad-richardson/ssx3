## The mechanism (orchestrator diagnosis)

T49 vs E37: VU1 **code** memory differs. PCSX2 at byte 0x10 = `B 0x258`
(`lo=40000048`), at 0x40 = `B 0x7d8` (`lo=400000f2`); the recomp runs
`LQI vf18,vf13` at 0x10 and a non-branch at 0x40. PCSX2's feeding packets
carry 38 `MPG` uploads (e.g. `num=0 addr=0`, `addr=256`, `num=64 addr=512`);
the recomp's trace window shows none. So the game's microcode uploads never
land and the "stuck" programs are stale code.

Cause, `ps2xRuntime/src/lib/ps2_memory.cpp` DMA chain walker (~1463–1541):
for the VIF channels it appends the DMAtag's upper 64 bits (the embedded VIF
stream, i.e. the TTE behavior) only for tag ids 1/2/5/6/7
(`compactVifLocalTag`, via `appendCompactVif1TagData`). For **REFE (0), REF
(3), REFS (4)** the tag's embedded VIF codes are dropped and only the
referenced data at `addr` is appended. A REF tag carrying `NOP; MPG num addr`
in its upper half with the microcode at `addr` therefore loses the `MPG`, and
the microcode bytes are parsed as VIF commands. Nothing checks CHCR.TTE
(bit 6).

Correct behavior: for VIF0/VIF1 chain transfers with CHCR.TTE=1, transfer the
tag's upper 64 bits into the VIF stream **for every tag id**, then the tag's
data (inline for CNT/NEXT/CALL/RET/END, from `addr` for REF/REFS/REFE). With
TTE=0, no tag bits enter the stream. Alternatives the runs separate: fix
lands the MPGs (VU1 code at 0x10 becomes `…40000048`) and the stuck programs
go to 0 ⇒ this was it; MPGs land but programs still stick ⇒ a second fault
downstream (table it, stop).
