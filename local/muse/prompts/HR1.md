## Facts
- Everything renders at PS2 native 512×448, paraLLEl-GS 1× (`SuperSampling::X1`), progressive scanout (ST1), alpha forced opaque (DK1). The phone stretches it ~2.9× with bilinear (`ps2_runtime.cpp:~3815-3830`).
- paraLLEl supports SSAA ×2/×4/×8/×16 and, from ×4, a high-resolution scanout built from the super-samples (`parallel-gs/gs/gs_interface.hpp:187-206`: `super_sampling`, the high-res scanout flag, `super_sampled_textures`, `dynamic_super_sampling`). Caveat in that comment: games that blit the framebuffer to the scanout location with textures lose the SSAA information; check whether SSX 3 does.
- Present path today (DK1 §1): paraLLEl `vsync()` → GPU→CPU readback (`ps2_gs_parallel_backend.cpp:280-322`, `copy_image_to_buffer` into CachedHost) → `PresentationFrame` → latch → raylib `UpdateTexture` (GL/GLES) → `DrawTexturePro`. The copy is where a 4× larger image costs CPU. On the Odin the GPU is 15–25 % busy and GameThread is the bottleneck (N11/NP1), so first measure which thread pays for the readback/upload.

## Goals, in order
1. **Knobs** (fork, default off = today): `PS2X_PGS_SSAA=1|2|4|8|16`, `PS2X_PGS_HIRES_SCANOUT=0|1`, wired into our paraLLEl backend's options and the presentation size (the presenter must accept a 1024×896-ish frame). Mac: frames at Select Peak and the race (jumps/edges) for 1× vs 4× vs 4×+hi-res, viewed and cropped side by side (send-ready PNGs in scratch); note any SSX 3 effect that breaks (blur/glow/fog passes that sample the framebuffer).
2. **Cost:** Mac speed (exclusive lease, ABBA, `PS2X_UNPACED=1` if the base has FP1) 1× vs 4×+hi-res, plus per-thread CPU (GameThread, GsWorker, main) so we know where the readback lands; the same on the **iPad** (one launch per config, fresh card, diagnostic pace; I33/F3 recipe).
3. **Skip the CPU copy (scope, and a Mac prototype if the time box allows):** present the paraLLEl image without a readback. Candidates: macOS/iOS: export the Vulkan image as an IOSurface (MoltenVK `VK_EXT_metal_objects` / IOSurface import) and bind it as a GL/GLES texture (macOS `CGLTexImageIOSurface2D`; iOS `CVOpenGLESTextureCache` with an IOSurface-backed `CVPixelBuffer`), with a GPU fence/semaphore for sync; Android: `AHardwareBuffer` shared between Vulkan (`VK_ANDROID_external_memory_android_hardware_buffer`) and GLES (`EGL_ANDROID_get_native_client_buffer` + `glEGLImageTargetTexture2DOES`). Alternative: draw the game image with Vulkan directly and keep raylib only for the overlay. Recommend one path per platform with an effort estimate; prototype on the Mac only if it fits.
Stop rules: if SSAA breaks SSX 3 visibly (wrong effects), report which and stop at goal 2. Everything behind env knobs, default off; guest state must be unaffected (det-hash identical 1× vs 4×: the backend can't change guest memory; GB8).
