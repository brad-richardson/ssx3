## The chain (orchestrator-verified)

1. `sub_0037A430` @`0x37a6a0` does `jalr $v1` to `0x396b40`. That's a
   small function: `w0 = (w0 & ~0x3C0) | 0x180` on the template at
   `*(a0+0xE84)`, i.e. set template mode 6. PCSX2 runs it (T64: pc
   `0x396b98`, then `0x37a6fc` ORs `0x30`, giving `0x1b0`).
2. `0x396b40` isn't in the function table. `games/ssx3/ssx3-functions.sweep.csv`
   has `sub_00396958` spanning `0x396958–0x3970f8`, but that range is really
   a cluster of tiny getters.
3. `dispatchGuestBranch` → `hasFunction` is false. The default
   `MissingFunctionPolicy::ContinueToTarget` returns true, so the call is
   **silently skipped**. Boot `e44e` logged
   `[guest-branch:missing-target] source=0x37a6a0 target=0x396b40` ×1040.
4. As a result, template 2 = `0x30` (mode 0), the rider item is mode 0, there
   are no mode-6 draw records, set-A microcode is never uploaded, and the 3D
   is missing.

Other missing targets in `e44e`: `0x30db90` (×25), `0x26a068`, `0x3b1140`,
`0x140bc0`, `0x284b50`/`0x2849b8`/`0x284940`, `0x144928`, `0x14e130`.
