# I33 Part 1 — paraLLEl-GS (GPU) on iOS: feasibility, Simulator + iPad (muse, 3 h)

## Why
iOS builds render with the CPU GS backend (F2 Part 3b: `PS2X_GS_SHADOW_PARALLEL` is off, the paraLLEl backend compiles to a stub). On the Mac, switching to paraLLEl made boots reach the race 1.87× faster and the race 1.67× faster with identical guest state (GB8). Brad plays on his iPhone, so this is likely the biggest iOS speed win available.

## Facts
- Mac recipe: `local/research/GB8/REPORT.md` (build flags, `PS2X_GS_BACKEND=parallel`, `GRANITE_VULKAN_LIBRARY` → Homebrew MoltenVK/loader), paraLLEl-GS fork `ssx3` `19d93b2` + Granite `166ba21a`; `PGS_HIER_BINNING=force` works on Apple GPUs (GB9). Progressive scanout is on (ST1).
- iOS recipe: `~/dev/ssx3-work/F2/ios/build-install.sh` (F1/F2 Part 3; deps in `~/dev/ssx3-work/ios-deps`), bundled env `local/research/I32/ps2x.env`, deploy `local/research/I31/deploy-ios.sh`. Fork `ssx3` `0ed07c4`; canonical codegen.
- iOS can't load a Vulkan loader dylib from Homebrew: MoltenVK must be linked/embedded (the LunarG Vulkan SDK ships `MoltenVK.xcframework` with iOS + iOS-simulator slices; check what's installed locally first — `ls /usr/local/share/vulkan ~/VulkanSDK /opt/homebrew/opt/molten-vk 2>/dev/null`). Granite loads Vulkan via volk/dlopen: find how `GRANITE_VULKAN_LIBRARY` is resolved and what an embedded framework path needs (cite file:line).
